# 新一代防封内核

`http://<主机>:8787/console/#/wrap`

这是单独的使用说明。安装、切换、订阅、更新都在这里。技术细节不在本页。

侧栏仍叫 **内核**。它和旧内核共用这一页：先选内核，再对选中的槽安装或切换。本页不创建槽，也不导入账号。空槽和出口仍走 [导入](./import)。

对照产品 **1.4.135**。控制面升级不会自动换成这个内核，也不会自动重启已经在跑的槽。

## 先准备什么

1. 槽已经创建，并且绑了出口。没有出口，导入和换票都会 `proxy_required`。
2. 只有这次会**新占**一个宿主订阅名额时，才需要本机订阅有效且还有剩余槽位。已经有有效许可的槽不用先腾出余量：同槽更新、同槽切换现行版本，以及仍有效的旧离线授权，都按原许可继续。Docker、KVM 和集群共用这一个额度，不按版本拆开。
3. 只在要换成这个内核的槽上操作。旧内核的槽可以继续跑，不必一起换。

登录页有 **免登录购买**。同一浏览器可 **查看订单**，支付交付后点 **应用到本机**。已经登录时，用侧栏 **订阅** 购买、续费、领码和激活。订单已发码，不等于本机已经兑换。

## 安装或切换

1. 打开内核页，选中目标槽。
2. 内核选 **新一代防封内核**。需要沿用旧授权时，选带「旧授权兼容」的下载项，不要选标准包。
3. 确认安装或切换。已有同槽订阅会沿用，不额外占一个名额。没有订阅、但宿主还有余量时，用剩余名额。
4. 等到槽重新可调度。切换会重启槽内进程，不删除槽，不重放已经发出去的请求。未拿到有效许可之前，不会先把槽停掉。

下面这些情况不用先单独做授权，再开槽：

- 新开一个槽并装上这个内核
- 把已有槽导入后切过来
- 只是把推理内核从旧内核换过来

宿主订阅的运行名额用满时，不能再新增启动。已经在跑的槽继续服务。停机、已经切回旧内核、或已经孤立的占位会被收回，不占用名额。

## 订阅额度怎么算

| 你看到的 | 含义 |
| --- | --- |
| 一个可用状态 | 本机订阅是否有效 |
| 剩余可绑定槽位 | 现在还能新开几台 |
| 已用 / 剩余 | 名册上正在占用的槽 |

- 同一张宿主兑换码从核销时自己计时。没到期的额度相加，到期只扣掉那一笔。
- 同一槽切换现行版本，沿用原来的许可，满额时不用再占一槽。
- 删掉槽、单槽或批量切回旧内核、以及这次内核安装，都会释放名额。
- 重装时已有同槽订阅则重签，否则使用剩余名额。普通绑定不会触发重签。

满额时如果仍要更新一台已经在跑的槽，可以更新，不会因为运行额度被拒绝。

## 日常使用

装上之后，调用方式不变。客户端仍打 `/v1/messages`、`/v1/chat/completions` 或 `/v1/responses`。密钥、粘性会话和出口规则见 [调用 API](../api) 与 [槽位与账号](../slots)。

使用时注意这些面板行为：

- **会话留在原槽。** 已经绑定的 Claude 或 Codex 续轮优先留在原槽。调高别的槽的等级或权重，不会把续轮迁走。新会话、以及粘性失效之后，仍按等级和选槽策略分配。
- **原槽暂时不可用。** 已经排队的 Claude 续轮继续等原槽。额度退水、不可调度、或粘性等待超时，仍按原来的规则换槽。
- **工具和图片。** 发给 Claude 的托管工具定义会保留。`zero` 布局下，结构化 system 原样传递。运行时不支持时，在本机返回具体字段错误，不发出请求，也不换号。
- **内嵌图片。** 工具结果里的图片会按原顺序保留。无法原样保留的输入，面板直接返回 400，不改写后重试。
- **续轮缓存。** 调用方的工具名、系统提示分块和缓存断点保持原位，避免续轮被重复改写。
- **遥测。** 可以在面板开关。只对这个内核的槽生效。停机的槽只记下设置；要生效就先排空，再重启内核，然后恢复原来的调度。面板会区分「已生效」和「已验证上传」。
- **主动查询额度。** Claude 槽可在列表、机架、用量弹窗或详情里手动刷新官方额度。它复用该槽凭证和出口，不发模型探测。同一槽同时点多次会合并。官方 429 时会退避，失败会明确报错。

调度被挡住时，原因表里的 `license_crag_host_over_quota` 表示宿主订阅满额。这不是账号被封，也不是出口故障。

## 更新

1. 先按 [更新](../upgrade) 升级控制面，确认关于页版本和 `/health`。
2. 本内核 **不会** 随控制面自动重装。Changelog 写「不需要 wrap-cli/sync、不重装槽」时，不要为了追版本去重装。
3. 只有准备换这一版内核时，才在内核页下载对应包，再对选中的槽确认安装。
4. 安装失败时，只有旧版本重新启动并通过鉴权健康检查，才会恢复运行。没通过就保持停止，并留着回滚包。
5. 订阅状态暂时读不到时，会在停槽之前直接返回错误，不会先停再报。

当前出厂和默认下载是 **3.1.4 标准版**。旧授权环境要显式选旧授权兼容包，不要让它去拉标准包。

## 更新之后看什么

- 关于页版本是目标版本，`/health` 为 200。
- 该槽仍可调度，官方初装没有变成「未登录」。
- 订阅页剩余槽位和实际在跑的槽一致。切走或删掉的槽不应继续占名额。
- 用升级前就能用的密钥打一次 `/v1/messages`。

## 不要做的事

- 不要因为控制面更新了，就重装所有槽。
- 不要在没拿到许可之前手动停槽。
- 不要把标准包装进仍依赖旧授权的槽。
- 不要用切内核解决出口、DNS 或 502。那些仍看 [常见问题](../../reference/faq)。
