# 内核

`http://<主机>:8787/console/#/wrap`

导航名字是 **内核**。这里安装、上传、同步槽内的 kernel，不创建槽，也不导入账号。

## 样本放在哪

默认样本目录是 `share/wrap-cli`。控制面用的主内核是 `KIN_KERNEL_BIN`，通常是 `bin/kin-kernel`。同步到槽里之后，槽跑的是同步过去的那一份，不是你磁盘上还没同步的新文件。

## 你能做的操作

- 安装发行版 kernel。更新 Changelog 标了 `wrap-cli/sync` 时用这个，或用安装脚本的默认同步，不要两个都做一半。
- 上传二进制。单文件上限 **32MB**。上传的是 kernel，不是整个镜像。
- 选数据面。槽上可见的值是 `wrap`、`cc`、`crag`。协议页把推理引擎固定成 rust cli-hop，这里不要再找一个 Go HTTP 转发开关，公开包里没有那条路。
- 把样本同步到选中的槽。同步重启槽内数据面，不 `docker rm` 槽，不重放已经发出去的请求。
- 从样本提升、或把当前槽打成新样本。提升之前先确认这台槽的初装是成功的，否则你会把一个未登录的样本复制出去。

## 更新之后必看

只升级了控制面、这一页的文件时间还是旧的，说明你用了 `--no-sync-wrap`，或者同步失败。新的请求仍走旧内核。把同步做完，再回虚拟机页看槽是否仍可调度。

控制面重启不会自动替换正在运行的槽内进程。
